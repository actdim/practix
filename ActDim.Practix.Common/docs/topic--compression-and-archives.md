# Stream & Payload Compression and Archiving

`CompressionManager` is an enterprise-grade compression and archive engine built entirely on top of the .NET 10 Base Class Library (BCL). It unifies stream compression (`GZip`, `Deflate`, `Brotli`), format auto-detection, and archive container streaming (`Zip`, `Tar`) under a zero-allocation, high-throughput pipeline.

---

## Architectural Principles & Zero-Heap Guarantees

Traditional compression libraries frequently trigger Garbage Collector stalls by allocating large byte arrays on the Large Object Heap (LOH) or creating unnecessary intermediate streams. `CompressionManager` strictly eliminates these bottlenecks:

1. **Recyclable Memory Stream Pooling (`MemoryManager.Default`)**:
   - Every scratch or output stream generated by `CompressionManager` is rented from `MemoryManager.Default` (a pre-configured `RecyclableMemoryStreamManager`).
   - Streams are returned to the caller positioned at `Position = 0`.
   - The caller owns the returned `MemoryStream` and is responsible for disposing it (returning its blocks to the pool).
2. **`ArrayPool<byte>.Shared` Rented Transfer Buffers**:
   - Streaming read and write loops rent 80 KB transfer buffers (`ArrayPool<byte>.Shared.Rent(BufferSize)`), keeping chunk allocations below the 85,000-byte LOH threshold.
   - Buffers are returned in `finally` blocks, guaranteeing zero buffer leakage even when operations are cancelled or fail.
3. **No Redundant Stream Buffering**:
   - The BCL codecs (`GZipStream`, `DeflateStream`, `BrotliStream`) maintain internal buffers. Wrapping them in `BufferedStream` or intermediate buffers is explicitly forbidden as it adds heap allocations and extra memory copy operations.
4. **Stack-Allocated Magic Byte Sniffing**:
   - Format detection inspects headers via `stackalloc byte[16]` and `ReadOnlySpan<byte>` slice comparisons, requiring zero heap allocations.
5. **Stream Ownership Contracts**:
   - **Produced Streams**: Streams created by `CompressAsync(...)` or `DecompressAsync(...)` without a destination stream are newly instantiated pooled streams owned by the caller.
   - **Destination Streams**: When a destination stream `dst` is passed by the caller, `CompressionManager` writes directly to `dst` at its current position and leaves it open.

## Codec & Container Support Matrix

| Category | Format | Magic Bytes / Signature | Detection | BCL Underlying Implementation |
| :--- | :--- | :--- | :---: | :--- |
| **Stream Codec** | `CompressionFormat.GZip` | `1F 8B` | Auto / Explicit | `System.IO.Compression.GZipStream` |
| | `CompressionFormat.Deflate` | None (raw RFC 1951) | Explicit only | `System.IO.Compression.DeflateStream` |
| | `CompressionFormat.Brotli` | None (raw RFC 7932) | Explicit only | `System.IO.Compression.BrotliStream` |
| | `BZip2`, `LZMA`, `7z` | `42 5A`, `5D 00`, `37 7A` | Sniffed | Unsupported (throws `NotSupportedException`) |
| **Archive Container** | `ArchiveFormat.Zip` | `50 4B 03 04` (`PK..`) | Auto / Explicit | `System.IO.Compression.ZipArchive` (Random Access) |
| | `ArchiveFormat.Tar` | `ustar` at offset 257 | Auto / Explicit | `System.Formats.Tar.TarReader` / `TarWriter` (Streaming) |

> [!IMPORTANT]
> **Brotli & Raw Deflate Limitations:**
> Brotli and raw Deflate streams are headerless bitstreams by specification. They cannot be auto-detected via magic bytes. Calling `DecompressAsync` without an explicit format on Brotli or raw Deflate data will throw `DataFormatException`.

## Complete API Reference & Examples

### 1. Payload & Buffer Compression

```csharp
ICompressionManager manager = new CompressionManager();

// Compress byte array into a pooled seekable MemoryStream
byte[] payload = GetRawData();
await using (Stream compressedStream = await manager.CompressAsync(payload, CompressionFormat.Brotli))
{
    // compressedStream is a RecyclableMemoryStream positioned at 0
    await httpClient.PostAsync("/upload", new StreamContent(compressedStream));
}

// Compress into an owned pooled buffer handle (zero heap array allocations)
using (IBufferOwner<byte> compressedBuffer = await manager.CompressToBytesAsync(payload, CompressionFormat.GZip))
{
    ReadOnlyMemory<byte> memorySlice = compressedBuffer.Memory;
    int validLength = compressedBuffer.Length;
    // Transmit or process buffer slice
} // Underlying array is safely returned to ArrayPool<byte>.Shared on Dispose
```

### 2. Stream-to-Stream Zero-Copy Pipelines

```csharp
// Compress source stream directly into destination stream
await using var fileIn = File.OpenRead("data.json");
await using var fileOut = File.Create("data.json.gz");

await manager.CompressAsync(fileIn, fileOut, CompressionFormat.GZip);
```

### 3. Decompression with Automatic Format Detection

For GZip, ZIP, and TAR archives, `CompressionManager` automatically sniffs the header from seekable streams:

```csharp
await using var incomingStream = File.OpenRead("payload.bin");

// Auto-detects GZip and decompresses into a pooled RecyclableMemoryStream
await using Stream decompressedStream = await manager.DecompressAsync(incomingStream);

// Or decompress directly into an owned pooled buffer:
using IBufferOwner<byte> decompressedBuffer = await manager.DecompressToBytesAsync(incomingStream);
```

## Archive Streaming & Inspection (`DecompressArchiveAsync`)

`DecompressArchiveAsync` provides a unified streaming visitor over ZIP and TAR archive entries without unzipping files to disk:

```csharp
await using var archiveStream = File.OpenRead("package.tar");

await manager.DecompressArchiveAsync(archiveStream, async (entry, openRead) =>
{
    Console.WriteLine($"Path: {entry.FullName}, Size: {entry.Size}, Modified: {entry.LastWriteTime}");

    if (entry.EntryType == ArchiveEntryType.RegularFile && entry.FullName.EndsWith(".json"))
    {
        // openRead() returns a non-seekable entry stream owned by CompressionManager
        await using Stream entryStream = await openRead();
        using var jsonDoc = await JsonDocument.ParseAsync(entryStream);
        ProcessConfig(jsonDoc);
    }

    return true; // Return true to continue traversal, or false to abort early
});
```

### Archive Entry Stream Rules:
1. **Synchronous Execution Window**: The `openRead` stream is only valid during the execution of the callback delegate. It is closed/disposed immediately after the delegate returns.
2. **Streaming Tar vs Seekable Zip**:
   - `Tar`: Requires sequential forward-only reading. Entries must be consumed in order.
   - `Zip`: Supports random-access entry lookups if `archiveStream.CanSeek == true`.

## Error Handling & Exception Specifications

- `ArgumentNullException` / `ArgumentException`: Thrown if streams are null, closed, or writeable streams are passed to read operations.
- `DataFormatException`: Thrown when a stream contains corrupted compression blocks or unsupported header magic bytes.
- `NotSupportedException`: Thrown when attempting to compress/decompress formats that have no BCL support (e.g. RAR, 7z, BZip2).
- `ObjectDisposedException`: Thrown if operations are invoked on disposed streams or buffer owners.
